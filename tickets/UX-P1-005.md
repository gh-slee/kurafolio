# UX-P1-005: Open any holding for its detail and keep filters while browsing

## Goal

The V2 pages answer "what do I own and what is it worth". The next question is about one line: where do I hold this fund, what did it cost, how has it moved, which import told the app about it. Give every row in a holdings table a detail view, and make filters and the chart range survive moving between pages, so a user can follow one thread without starting over.

## Context

### Background

- The shipped application had no drill-down, and its selections were lost on every navigation. V2 pages fix the second for currency; this ticket extends it to filters and range.
- The original criteria in [ux-p1-005-analysis.md](../docs/ux-p1-005-analysis.md) refer to saved editions, which V2 does not have. This ticket replaces them.

### Scope

- In scope: one detail endpoint and view for a security or a coin, filters and range kept in the address bar, locale keys, tests.
- Out of scope: performance or return figures (UX-P1-002), dividends (UX-P1-003), editing or deleting a holding, notes or tags, the shipped SQLite application.

### Implementation notes

- Design: read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [ui-design-workflow.md](../docs/ui-design-workflow.md) first. Keep the existing identity: flat bordered panels, the theme variables in `frontend/src/styles.css`, the existing button, field and status-tag primitives, no new fonts, shadows or colours. A new section goes in the "deeper analysis" part of the page skeleton, below the holdings table, and never above the value and chart. Put the date, currency and unit next to each figure, and show an unknown or partial figure as such instead of a reassuring total. Wording is factual and calm and never reads as trading advice.
- Detail shows, for one instrument: quantity and value per account, book cost and unrealized gain where the source gave cost (a dash otherwise), the price with its "as of" time and provider, the daily value line for that holding with estimated days marked as on the main chart, the share of the portfolio, the source and date of the last import that included it, and for a fund a link to its rows on the Exposures page.
- The detail view is a route (`/app/investments/holding/{id}` and the crypto equivalent), so it can be bookmarked and the back button works. Use the opaque instrument ID from the analysis contract, never a ticker, in the address.
- Filters (account, currency, search text) and the chart range go in the query string. Display currency stays a preference.
- One new read route, for example `GET /api/v2/analysis/holdings/{id}`, built on the same calculation as the page so a number never differs between the table and the detail. Extend the WL-P0-012A contract; do not compute in the browser.
- A holding that left the portfolio (treated as sold after a newer import) answers with a "no longer held" state, not an error.

### Where to start

- The analysis service and DTOs from WL-P0-012A and the series from WL-P0-009D in `src/kurafolio/web_v2/`.

## Acceptance criteria

- [ ] Given a holdings table, when the user activates a row by mouse or keyboard, then the detail view opens, and Back returns to the table with the same filters, sort and scroll position.
- [ ] Given a fund held in two accounts, then detail lists both with quantities and values that sum to the table row.
- [ ] Given a holding whose source gave no cost, then cost and gain show a dash and a short reason.
- [ ] Given a filter and a three-month range on Stock/Bond, when the user opens Total and returns, then both are still applied; a reload keeps them.
- [ ] Given a detail address for another user's holding or an unknown ID, then the answer is not-found and nothing is revealed.
- [ ] Given a holding that is no longer held, then the view says so and shows its last known date.
- [ ] Every amount names its currency and every price its "as of" time.
- [ ] Keyboard reachable, one `h1`, labelled controls; en-CA, zh-TW, zh-CN; light and dark; 375 px and 1024 px.

### Tests

- Contract tests with fixed oracles for the detail route, including tenant isolation.
- A browser spec for open, back, filter persistence and the no-longer-held state.
