# ENG-115: Route each ticket tier to a model and add per-tool agent definitions

## Goal

The owner wants to start a session in Claude Code, Codex or OpenCode, say "plan <ID>" or "pick up <ID>", and have the right model do the work, for anyone who clones the repository. The spec workflow (ENG-112) defines roles by tier. This ticket assigns models to tiers and adds the tool configuration that makes a session hand planning and building to those models.

## Context

- Verified on 2026-11-17: Claude Code reads AGENTS.md when there is no CLAUDE.md; its project subagents accept `model` and `effort`. Codex reads custom agents from `.codex/agents/*.toml` with `model` and `model_reasoning_effort` (from documentation; not tried); project config loads only for trusted projects. OpenCode reads AGENTS.md and project agents from `.opencode/agents/`; its model IDs include a personal provider name.
- `.codex/` is gitignored and `scripts/check_publication.py` rejects `.claude/agents/`, `.codex/agents/` and `.opencode/agents/`.
- `docs/agent-development.md` currently allows subagents only when explicitly requested.
- A session whose builder agent fails to load silently builds on its own model; the design must make that visible.

## Requirements

- AGENTS.md gains a model-to-tier table, chosen by the owner, with a rule: a session that cannot reach the model for a role stops and says so; it never builds a ticket above its tier.
- Claude Code: project agents for planner, builder and reviewer, each with `model` and `effort` set, so routing does not depend on personal settings.
- Codex: a project builder agent with `model` and `model_reasoning_effort` set.
- OpenCode: no tracked model ID that is specific to one person's provider.
- Each agent states its model in its first output, and the builder records it in the ticket Log.
- The publication guard and `.gitignore` allow exactly the new agent files, with tests.
- Non-goals: changing anyone's global configuration; enforcing the Build plan gate (ENG-116).

## Acceptance criteria

- [ ] AC-ENG-115-01: AGENTS.md has the model-to-tier table and the stop-if-unavailable rule.
- [ ] AC-ENG-115-02: In a fresh Claude Code session, the planner and builder agents report the configured models and effort; evidence recorded in the PR.
- [ ] AC-ENG-115-03: In a fresh Codex session, the builder agent reports the configured model and effort, or the PR records why that could not be shown.
- [ ] AC-ENG-115-04: The publication guard accepts exactly the new agent files and still rejects the rest of `.codex/` and `.agents/`; tests cover both.
- [ ] AC-ENG-115-05: With the builder agent file renamed, a Claude Code session asked to build stops instead of building on its own model.
- [ ] AC-ENG-115-06 [review]: No tracked file contains a provider name or path specific to one person.
