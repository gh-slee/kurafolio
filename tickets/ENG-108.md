# ENG-108: Review the owner's feedback after two weeks on the MVP and re-rank what follows

## Goal

The owner chose an MVP first so that real use decides what comes next (PRODUCT_CONTEXT.md, 2026-11-10). That only works if the feedback is collected and turned into tickets. Two weeks after the owner starts using the MVP with their own data, gather what they noticed, file it, and re-rank the P1 and P2 backlog with them.

## Context

### Background

- The P1 and P2 order on 2026-11-13 is a planner's estimate. The owner's daily use is better evidence.

### Scope

- In scope: a feedback list from the owner, a ticket for each item worth doing, an updated P1 and P2 order in ROADMAP.md, Gate A requests for the top items.
- Out of scope: implementing anything; looking at the owner's real data (the owner describes what they saw; no agent opens the real instance).

### Implementation notes

- Ask about the flow in PRODUCT_CONTEXT.md step by step: registering, enabling plugins, each import, each analysis page, refresh, currency switch, download.
- For every item record: what the owner did, what they expected, what happened, how often it matters.
- Sort items into: defect (P0 if it shows a wrong number or blocks the flow), go-live gap, post-go-live idea, or not doing with the reason.
- Reproduce defects on synthetic data before filing them.

### Where to start

- [PRODUCT_CONTEXT.md](PRODUCT_CONTEXT.md), [ROADMAP.md](ROADMAP.md).
- `python3 scripts/tickets.py list --priority P1` and `--priority P2`.

## Acceptance criteria

- [ ] A dated feedback section in PRODUCT_CONTEXT.md lists each item in the owner's words.
- [ ] Every item has a ticket or a recorded "not doing" with the reason.
- [ ] Wrong-number and flow-blocking defects are filed as P0 with a synthetic reproduction.
- [ ] ROADMAP.md shows the P1 and P2 order the owner confirmed.
- [ ] `python3 scripts/tickets.py check` passes.

## Plan

- [ ] Owner says the two weeks are up, or asks earlier.
- [ ] Walk the flow with the owner and record items.
- [ ] Reproduce defects on synthetic data.
- [ ] File tickets and re-rank.
- [ ] Owner confirms the order.

## Handoff

- State: Not started. Starts when the owner has used the MVP.

- Verify: `python3 scripts/tickets.py check`
- Gotchas: Ticket text is public: no account names, amounts or holdings from the owner's real data.
- Open questions: None.
