# ANL-104: Show a rate of return where the records support one

## Goal

"How much have I made, as a percentage, this year?" is the question every investor asks. A correct answer needs every deposit and withdrawal in the period. Once activity records exist (ANL-103), show a money-weighted return for periods that are fully covered, and say exactly why when it cannot be shown.

## Context

### Background

- Waits for ANL-102, where the owner decides whether Kurafolio records transactions at all. The approved baseline tracks holdings and purchases only and the owner asked for "no recorded cash flows" (PRODUCT_CONTEXT.md).
- A wrong return figure is worse than none. This ticket is as much about refusing to show a number as about showing one.
- ANL-101 already explains value changes without claiming a return.

### Scope

- In scope: eligibility rules, a money-weighted return (XIRR) and a simple gain figure for covered periods, the reasons shown when not eligible, tests with independent oracles.
- Out of scope: time-weighted return (needs a valuation at every cash flow, which the product does not have as facts), benchmarks (ANL-108), after-tax return, projections.

### Implementation notes

- Design: read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [ui-design-workflow.md](../docs/ui-design-workflow.md) first. Keep the existing identity: flat bordered panels, the theme variables in `frontend/src/styles.css`, the existing button, field and status-tag primitives, no new fonts, shadows or colours. A new section goes in the "deeper analysis" part of the page skeleton, below the holdings table, and never above the value and chart. Put the date, currency and unit next to each figure, and show an unknown or partial figure as such instead of a reassuring total. Wording is factual and calm and never reads as trading advice.
- Four separate figures, never merged: change in value, net contributions, investment gain (change minus contributions), and annualized money-weighted return.
- Eligible means: a valuation from imports at both ends of the period, and activity records covering the whole period for every account in scope. Estimated days (MKT-009D) cannot be period ends.
- Periods shorter than a year show the period return and do not annualize.
- Define before coding: the solver's behaviour when there is no root or more than one, the day-count rule, how fees and dividends enter, and the currency in which flows are valued (rate on the flow date).
- Label the figure "money-weighted return" with a one-line explanation. Do not call it "performance" without the qualifier.

### Where to start

- The activity records from ANL-103.
- The series from MKT-009D and its estimate flags.

## Acceptance criteria

- [ ] Given a start value of 10,000, one deposit of 1,000 at mid-year and an end value of 12,100 after one year, then investment gain is 1,100 and the money-weighted return matches an independently computed value to four decimals.
- [ ] Given a period with a missing month of activity records, then no return is shown and the reason names the gap.
- [ ] Given a period ending on an estimated day, then the end snaps to the last import date or the figure is withheld, and the page says which.
- [ ] Given a three-month period, then the return is not annualized.
- [ ] Given flows with no solution or two solutions, then the page says the rate cannot be determined.
- [ ] Negative values, a zero starting value and mixed currencies each have an oracle test.
- [ ] An independent finance review signs off the method statement shown to the user.
