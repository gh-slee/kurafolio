# APP-109: Hide balances on demand and polish tables and charts on a phone

## Goal

People open a portfolio app on the bus and share their screen at work. Add a one-tap "hide amounts" mode that masks every money figure while keeping percentages and charts' shapes, and tidy the dense tables and charts for a phone beyond the basic 375 px checks the go-live pages already pass.

## Context

### Background

- Balance privacy is a small feature that users of every consumer finance app expect.
- The mobile shell and navigation are done in APP-011A. What remains is page-level: wide tables, chart tooltips and touch targets.

### Scope

- In scope: a hide-amounts toggle in the top bar, masking of every amount in text, tables, chart axes and tooltips, a compact holdings table layout under 480 px, touch-sized controls, tests.
- Out of scope: an installable app or offline mode, a passcode or biometric lock, hiding amounts in downloads, native apps.

### Implementation notes

- Design: read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [ui-design-workflow.md](../docs/ui-design-workflow.md) first. Keep the existing identity: flat bordered panels, the theme variables in `frontend/src/styles.css`, the existing button, field and status-tag primitives, no new fonts, shadows or colours. A new section goes in the "deeper analysis" part of the page skeleton, below the holdings table, and never above the value and chart. Put the date, currency and unit next to each figure, and show an unknown or partial figure as such instead of a reassuring total. Wording is factual and calm and never reads as trading advice.
- Masked amounts are replaced in the accessible text too, not only visually. A screen reader must not read the hidden number.
- Percentages, weights and the chart's shape stay visible; the value axis loses its labels.
- The toggle state is kept in the browser only, per device, and defaults to shown. It is not a security control and the page does not say it is.
- On a phone the holdings table shows name, value and weight, with the other columns behind a row expansion. No horizontal page scroll.
- No financial data, credential or session token goes into persistent browser storage or a service-worker cache (docs/web-frontend.md).

### Where to start

- `frontend/src/v2/shell.tsx`, the analysis pages from ANL-012B to 012E, `frontend/src/components/data-table.tsx`, `chart.tsx`, `frontend/src/lib/format.ts`.

## Acceptance criteria

- [ ] Given hide-amounts is on, then no money figure appears in the page text, the accessibility tree, chart tooltips or axis labels on any analysis page; percentages remain.
- [ ] Given a reload, then the choice persists on that device; given sign-out, then no financial data remains in browser storage.
- [ ] Given a 375 px screen, then the holdings table needs no horizontal scroll and every control meets the design system's 42 px minimum target height.
- [ ] Given a download while amounts are hidden, then the dialog says the file will contain the amounts.
- [ ] Keyboard, zoom to 200% and screen-reader labels work for the toggle and the row expansion.
- [ ] en-CA, zh-TW, zh-CN; light and dark.

### Tests

- A browser spec that searches the rendered text and accessibility tree for the fixture's amounts with the mode on.
