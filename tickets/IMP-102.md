# IMP-102: Add optional scheduled or folder-watch imports

## Goal

Let an operator point the instance at a folder, so that an export file saved there is picked up and offered to the user as an import to review. It would save the upload step. The export from the institution and the review and confirmation stay manual.

## Context

### Background

- Recommendation: close this ticket. No owner request is on record. It saves one click per import and adds a process that reads the host's file system and a new place where a private file can sit unnoticed, which is against the "imported files are not stored" rule.
- Real automation of imports is the API connector (PLG-102), which removes the manual export as well.

### Scope

- In scope: only if the owner keeps it: a watched folder per user configured by the operator, pick-up into the normal preview, removal of the file after normalization.
- Out of scope: auto-confirmation, watching a cloud drive, treating a missing file as "no activity".

### Where to start

- The import worker from IMP-007F and the import routes from IMP-007E.

## Acceptance criteria

- [ ] A file in the watched folder appears as an import awaiting review; nothing is booked without confirmation.
- [ ] The file is removed from the folder after normalization, successful or not, and never copied elsewhere.
- [ ] A missing file is never treated as zero activity.
- [ ] The feature is off by default and one user's folder is never read for another user.

## Plan

- [ ] Owner decides: close, or keep.
- [ ] If kept: Gate A, then design the folder-to-user mapping with a security review.
