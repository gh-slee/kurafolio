# IMP-008: Release the raw slot of a native-rejected member during cleanup

## Goal

A member whose context is `native_discovery_v1` is refused before any launch and
its whole set becomes `REJECTED`. The attempt still owns the raw slot and the
set's storage reservation, but it has no launcher handle, so cleanup can never
produce the proof that `cleanup_set_v1` requires. Release that slot and the
storage reservation exactly once, without freeing any raw slot that could still
have a live child.

## Context

- The refusal path is in [worker.py](../src/kurafolio/ingestion/worker.py): it
  finishes `rejected/import_evidence_unsupported` with an empty proof list and
  makes no launcher call. This is the D12 behaviour from IMP-007F (`spec_approved`
  sha256:d76ee634c12ec2dacaaa7ec5670ac8ea8f69c0f1bc0c214b5617377ccce8baf6).
- The affected PostgreSQL row is
  `tests/test_postgres_worker.py::WorkerPostgresTests.test_ac_10_native_context_is_rejected_before_any_launch`.
  It records `members.state = 'rejected'`, `sets.state = 'REJECTED'`,
  `cleanup_state = 'failed'`, `leases.raw_slot = 'held'` and a non-zero storage
  reservation after repeated cleanup claims.
- [cleanup_set_v1](../src/kurafolio/persistence/ingestion_schema.py) releases a
  bound attempt only from a proof that names its job and fence. A never-bound
  attempt releases by elapsed raw deadline. A bound attempt with no launcher
  handle has no proof, so it waits forever.
- The `ingestion-schema-sql` resource is shared with IMP-007Q, which owns the
  late-proof slot release. This ticket does not claim exclusive ownership of
  [ingestion_schema.py](../src/kurafolio/persistence/ingestion_schema.py); the
  planner decides how the two releases relate before building. Do not change SQL
  from IMP-007F.
- The worker already treats a `launcher_instance_id` as the only source of a
  proof and never fabricates one. Keep that rule; the SQL owner decides how to
  represent an attempt that was refused before launch.
- Filed from the IMP-007F **sixth** review, not the fifth.
- Owner decision 2026-11-26: this ticket must land before IMP-007U exposes the
  upload route. The planner updates IMP-007U's `depends_on`; this ticket does not
  edit IMP-007U.
- Proposed AC for the planner: a PostgreSQL case shows the refused native
  member's raw slot and storage reservation released exactly once, and a second
  cleanup changes nothing. The existing AC entries below remain the planner's
  gated work.
- Planner trace of the merged code (`main` at `574896b`):
  - The worker claims first, then refuses. `ImportWorker._handoff` calls
    `claim_member_v1` with the handoff token, so the refused attempt is a bound
    lease (`token_digest` set). `_normalize` then calls `_context`, which raises
    `import_evidence_unsupported` for `payload_kind: native_discovery_v1` before
    any `launcher.start`. `_proof_wait` returns `None` when there is no handle,
    so `finish_member_v1` gets `outcome: rejected`, `error_code:
    import_evidence_unsupported` and `cleanup_proofs: []`.
  - Finish then records the lease `finished` with `raw_slot='held'` and
    `cleanup_proof_bytes` left NULL. The member becomes `rejected` with that error
    code, and the set becomes `REJECTED` with `cleanup_state='pending'`.
  - `_cleanup_once` skips journal records without a handle, so it sends
    `cleanup_proofs: []`. In `cleanup_set_v1` the bound attempt matches no proof,
    so it counts as `waiting`: the result is `cleanup_pending`, the set becomes
    `failed`, and the slot and storage reservation stay held. When an outcome is
    `purged` or `already_purged`, the worker removes the set's journal records.
  - The error code alone does not show a pre-launch refusal. After a launch,
    `_run_child` can return `('rejected', error.code)` with the child's
    discovery error, and that includes `import_evidence_unsupported`. Proofs are
    built by the worker from launcher status, and SQL checks only their shape.
  - SQL does have its own evidence of the context kind. `claim_set` builds the
    member's `context_bytes` itself, with `payload_kind` set to `parser_v2` or
    `native_discovery_v1` (`ingestion_schema.py`, around line 2597). On `main`
    no worker launches a native context. IMP-007Z (backlog) plans to change that.
  - The leases branch of `_transition_v1` already loads the attempt's `member`
    row for every normalize lease (around line 5148). Its raw-slot rule allows
    `held → released` for two cases only: never bound and past 120 s, or a
    non-empty proof array whose proofs all say `absent` or `not_created` for this
    fence (around line 5192).
  - IMP-007R (#114) changed `cleanup_set_v1` without touching
    `EXPECTED_STRUCTURE_SHA256` or `tests/fixtures/ingestion/oracle.json`. A
    change to a function body alone has not needed new inventory hashes.
  - The light CI job counts skipped PostgreSQL tests:
    `.github/workflows/ci.yml` runs `test_postgres_*.py` with
    `--expect-skipped 172`. Each new PostgreSQL test method raises that count.

## Requirements

- Add a fenced, exactly-once release for a normalize attempt that the worker
  finished `rejected/import_evidence_unsupported` without a launch, or define the
  equivalent database state and cleanup rule.
- Never release a slot that still has a live child or an unproven launcher
  handle. A later duplicate cleanup must not release it again.
- Keep the existing proof rule for bound launched attempts and the raw-deadline
  rule for never-bound attempts.
- Change only the SQL, its PostgreSQL tests (including the AC-10 worker case that
  AC-IMP-008-01 names), acceptance-ID tags in existing unit tests, the CI
  skipped-test count and the docs that describe this leak. IMP-007F's worker and
  launcher keep their current calls; if a call must change, record the interface
  decision in the ticket before building.
- The native-refusal release applies only while no merged worker launches a
  `native_discovery_v1` context. The change that starts launching native members
  (IMP-007Z) removes or replaces this release in the same pull request.
- Preserve append-only evidence, stable IDs and the storage reservation
  accounting.

- Design (D1 = A). A normalize attempt is a native pre-launch refusal when all
  of these hold:
  - the lease is `work_kind='normalize'`, `state='finished'`,
    `raw_slot='held'`, `token_digest IS NOT NULL` and
    `cleanup_proof_bytes IS NULL`;
  - its member has `state='rejected'`, `error_code='import_evidence_unsupported'`,
    and `context_bytes` whose `payload_kind` is `native_discovery_v1`.

  Such an attempt releases its raw slot once, in `cleanup_set_v1` only, after
  the same raw deadline as a never-bound attempt
  (`n >= created_at + interval '120 seconds'`). It writes no proof.

  The basis is that SQL built the context itself and no merged worker launches a
  native context. The member error code and the absence of any recorded proof
  narrow the rule to the one path the worker takes. The 120-second gate covers
  any raw buffer the API may still hold. Every other held slot keeps today's
  rules: the proof rule for bound attempts, the deadline for never-bound ones.
