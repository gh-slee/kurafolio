# UX-P2-004: Show backup, version and health status to the administrator

## Goal

A self-hosted instance holds data nobody else backs up. Today the operator learns about backups, versions and failed refreshes only from the documentation and the logs. Give the administrator a Status section in App Settings that shows the running version, when the last backup was taken, whether prices, rates and fund holdings are refreshing, and what to do about each, with the commands to run on the host.

## Context

### Background

- Backup and restore stay host commands by design: a browser that can restore a database can also destroy one.
- Two-factor sign-in was part of this ticket and is now WL-P2-010. Access from other devices is WL-P1-019.

### Scope

- In scope: a read-only status route for the administrator, the Status section, copyable host commands, a clear split between "download my data" and "back up the instance", documentation.
- Out of scope: starting a backup or restore from the browser, off-site upload, alerting by e-mail or push, user management (WL-P1-017).

### Implementation notes

- Design: read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [ui-design-workflow.md](../docs/ui-design-workflow.md) first. Keep the existing identity: flat bordered panels, the theme variables in `frontend/src/styles.css`, the existing button, field and status-tag primitives, no new fonts, shadows or colours. A new section goes in the "deeper analysis" part of the page skeleton, below the holdings table, and never above the value and chart. Put the date, currency and unit next to each figure, and show an unknown or partial figure as such instead of a reassuring total. Wording is factual and calm and never reads as trading advice.
- "Last backup" can only be known if the backup command records it. Add a small marker the documented backup command writes; if none exists the page says "no backup recorded", not "never".
- A backup contains every user's data and the secrets needed to read it. The page says so, and says a backup belongs on a different device.
- A user's own export (downloads) is not a backup. Both the user page and the administrator page say which is which.
- Refresh status reuses what WL-P0-009B and WL-P0-010A already expose; do not add a second scheduler view.
- Non-administrators never see instance status.

### Where to start

- The V2 operator documentation and backup procedure from WL-P0-021; [web-backups.md](../docs/web-backups.md) for the wording used in the shipped application.
- The App Settings page from WL-P0-011F; the refresh status routes from WL-P0-009B and WL-P0-010A.

## Acceptance criteria

- [ ] Given the administrator, then Status shows version, last recorded backup, and the last successful refresh of prices, rates and fund holdings, each with its time.
- [ ] Given no recorded backup, then the page says so and shows the documented command.
- [ ] Given a refresh failing for more than a day, then it is marked stale with a pointer to the log command.
- [ ] Given a non-administrator, then the section and its route are not found.
- [ ] The page explains the difference between a personal download and an instance backup in two sentences.
- [ ] Nothing on the page starts a backup, a restore or an upgrade.
- [ ] en-CA, zh-TW, zh-CN.
