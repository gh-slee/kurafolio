# WL-P1-017: Let the administrator manage users and registration in the browser

## Goal

One instance serves several people (owner decision 2026-11-10). Today the administrator can issue and revoke invitations in the browser, but seeing who has an account, disabling one, or helping someone who forgot a password needs a command on the host. The owner also decided that registration is invite-only by default with an administrator switch that opens self-registration, to be built after the MVP. Add a Users section for the administrator with these controls.

## Context

### Background

- Without it, inviting family means the owner must use a terminal for every forgotten password.
- Host commands stay as they are and remain the recovery path when the administrator is locked out.

### Scope

- In scope: list users with status and last sign-in, disable and enable a user, issue a one-time password-reset link, the self-registration switch, audit records, locale keys, tests.
- Out of scope: a second administrator or roles, deleting a user or their data, e-mail delivery, seeing another user's financial data (never), two-factor sign-in (WL-P2-010).

### Implementation notes

- Design: read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [ui-design-workflow.md](../docs/ui-design-workflow.md) first. Keep the existing identity: flat bordered panels, the theme variables in `frontend/src/styles.css`, the existing button, field and status-tag primitives, no new fonts, shadows or colours. A new section goes in the "deeper analysis" part of the page skeleton, below the holdings table, and never above the value and chart. Put the date, currency and unit next to each figure, and show an unknown or partial figure as such instead of a reassuring total. Wording is factual and calm and never reads as trading advice.
- The administrator never sees or sets another user's password. A reset is a one-time link with a short expiry that the administrator hands over, like an invitation; using it ends that user's sessions.
- The administrator cannot disable their own account or the last active administrator.
- Disabling ends the user's sessions at once and keeps their data untouched.
- The self-registration switch is off by default, shows its state on the sign-in page only as "registration is open" when on, keeps the existing registration rate limits, and every change is audited. The page warns that an open instance on a public address lets anyone create an account.
- New SQL functions follow the identity pattern: tenant and role checks inside the function, a new migration revision after the latest one, grants to the gateway role only. Read WL-P0-011I's Handoff for how a revision is added.
- The user list shows identity fields only. No balances, counts of holdings or import history.

## Acceptance criteria

- [ ] Given the administrator, then a Users page lists every account with status, creation date and last sign-in, and no financial information.
- [ ] Given a non-administrator, then the page and its routes answer as not found.
- [ ] Given the administrator disables a user, then that user's next request is refused and their data is unchanged; enabling restores access.
- [ ] Given the administrator issues a reset link, then it works once, expires, ends the user's sessions when used, and the administrator never sees a password.
- [ ] The administrator cannot disable themselves.
- [ ] Given self-registration is switched on, then a visitor can register without an invitation; switched off, they cannot. The default is off.
- [ ] Each of these actions writes an audit record naming the actor and the target, without secrets.
- [ ] A restore from backup keeps the documented behaviour: sessions revoked and credentials quarantined.
- [ ] en-CA, zh-TW, zh-CN; keyboard reachable; destructive actions ask for confirmation.

## Decisions needed

1. Whether password reset by link is offered in the browser at all, or stays host-only. Recommendation: offer it; a link the administrator must hand over in person or by a private channel is no weaker than an invitation.
