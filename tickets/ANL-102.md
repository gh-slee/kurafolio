# ANL-102: Decide whether Kurafolio records transactions, and what that unlocks

## Goal

The approved baseline knows what the user holds and what they bought, and deliberately records no cash flows. That keeps it simple, and it also rules out the things investors ask for next: rate of return, dividends received, contributions, benchmarks and tax cost. Six tickets wait on this single choice. Lay out the options with their cost and their data needs so the owner can decide whether to stay with the baseline, or add transaction records, and in which order.

## Context

### Spec material

- Background only: the revision 1 planning draft [docs/specs/v2-drafts/WL-P2-002.md](../docs/specs/v2-drafts/WL-P2-002.md) (sha256:1a87b1879919ab0ba57f793f3bc84caf432cd4c79743e97af62445b8e0f08c00). Where it differs from this ticket, this ticket applies.

### Background

- Waiting tickets: ANL-103 (activity and contributions), ANL-104 (rate of return), ANL-105 (income and corporate actions), ANL-108 (benchmarks and risk), ANL-109 (goals), RPT-102 (tax cost exports).
- At go-live the user already sees unrealized gain (value minus book cost) where the broker file gives cost, and ANL-101 explains value changes. Those cover "how am I doing" roughly. A true rate of return needs dated deposits and withdrawals, which only a transaction export provides.
- This is a decision ticket. It produces a paper and an answer, not code.

### Scope

- In scope: an options paper, a check of what the two built-in institutions export beyond holdings, the owner's decision, follow-up scope for the waiting tickets.
- Out of scope: building any mode; tax advice; changing how the baseline values Bitcoin.

### Implementation notes

- Options to describe, each with what the user gains, which export it needs, the size of the work and the risks: (A) stay with the baseline; (B) import broker activity exports to get deposits, withdrawals, buys, sells and dividends, which unlocks contributions, a money-weighted return and income; (C) B plus lot-level cost for realized gains and a Canadian adjusted-cost-base report; (D) verified balances for crypto held outside an exchange.
- For B, verify on synthetic fixtures what the broker's activity export contains and whether it can be reconciled with holdings snapshots without double counting. Use the format documentation and an invented file; never a real one.
- State plainly what stays impossible in each option. Example: a time-weighted return needs a valuation at every cash flow, which daily estimated values (MKT-009D) do not provide as facts.
- Any tax-related output is evidence for the user's own filing, never a tax calculation or advice, and never a statement about registered-plan contribution room.
