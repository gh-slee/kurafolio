# ENG-121: Run every test that reads ticket files on the light CI path

## Goal

ENG-120 gives a change that touches only `tickets/` a light CI path that runs `tests/test_tickets.py` and skips the rest of the suite. Other test modules also read files under `tickets/`, so a ticket-only change can pass the light path and then fail the full suite on the next change that runs it. Make sure every test that depends on files under `tickets/` runs whenever those files change, without giving up the light path for ordinary ticket edits.

## Context

- Source: ENG-120's outcome line and Handoff on pull request 78 (branch `ticket/eng-120-cut-the-pull-requests-and-ci-runs-that-o`, commit `d9f1451`). The outcome line says the Build plan "did not say that the light path should also run `test_agent_definitions.py`, which reads `tickets/README.md` (follow-up needed)". The Handoff names the risk: "a ticket-only edit of the quick start can pass light CI and fail on `main` later". The independent review of pull request 78 raised the same gap as a medium finding; the Build plan fixed the scope, so the builder left it for this ticket.
- How the light path works on that branch:
  - `scripts/ci_changes.py`: `is_ticket_only(paths)` is true when every changed path starts with `tickets/`. `decide()` applies it to `pull_request` events (diff from the merge base) and to `push` events (diff from the previous head), so a ticket-only push to `main` also takes the light path.
  - `.github/workflows/ci.yml`, job `python-312-linux`: when `ticket_only` is true it runs `python scripts/tickets.py check` and `unittest discover -s tests -p 'test_tickets.py'`, and skips the full `unittest discover`, the four demo reports and the other jobs. The language and publication checks run on both paths.
  - `scripts/check_pr_image.py` uses the same `is_ticket_only` to skip the image build.
- Test modules that read files under `tickets/` (on the ENG-120 branch):
  - `tests/test_tickets.py`: already on the light path.
  - `tests/test_agent_definitions.py`:
    - `test_builders_mark_done_in_their_last_commit` reads the "Quick start for an agent" section of `tickets/README.md` and asserts exact phrases (AC-ENG-120-01).
    - `test_gate_a_goes_with_the_filing_or_plan_pull_request` asserts phrases in `tickets/README.md` (AC-ENG-120-03).
    - `test_no_personal_provider_ids_or_paths` scans every tracked `.md` file, which includes every ticket file, for provider-qualified model IDs. Any ticket file can therefore fail this test, not only the rule files.
  - `tests/test_publication.py` names `tickets/` paths only as inputs to `path_allowed` and in synthetic repositories; it does not read the real files. `scripts/check_publication.py --worktree` already runs on the light path.
- Re-measure this list before building: ENG-120 may change before it merges, and later tickets may add tests that read `tickets/`.
- Re-measured while planning, on `main` at `301588b` (2026-11-25). ENG-120 merged in pull request 78; the light path, `ci_changes.py` and `check_pr_image.py` are as described above.
  - The only light-path step is "Run the ticket tests": `PYTHONPATH=src python -m unittest discover -s tests -p 'test_tickets.py' -v`, with `if: needs.changes.outputs.ticket_only == 'true'`. `unittest discover -p` takes one glob, and `tests/` has no `__init__.py`, so a second module needs either named modules on `PYTHONPATH` or a second step.
  - Modules under `tests/` that mention `tickets/`, `'tickets'`, `ls-files` or a glob of the repository root: `test_agent_definitions.py`, `test_ci_changes.py`, `test_pr_image.py`, `test_publication.py`, `test_tickets.py`. Only `test_tickets.py` (`load_tickets(ROOT)`) and `test_agent_definitions.py` (`tickets/README.md`, and every tracked file through `git ls-files`) read real files under `tickets/`. `test_ci_changes.py` and `test_pr_image.py` (both added by ENG-120) write `tickets/` files only in synthetic repositories; `test_publication.py` names `tickets/` paths as `path_allowed` inputs and reads `docs/specs/`, not tickets.
  - The provider-ID scan in `test_agent_definitions.py` never names `tickets/`: it lists every tracked file with `git ls-files`. A detector that looks only for the string `tickets/` finds this module today because of its other tests, not because of the scan.
  - `PYTHONPATH=src:tests python -m unittest -v test_tickets test_agent_definitions` ran 44 tests in about 5 seconds locally, with no Docker. `test_agent_files_stay_out_of_the_image_context` calls `docker_context.prepare_context`, which copies files and needs no Docker daemon.
  - Documents that describe the light path: only `docs/development.md` ("A small `changes` job first decides ...", which names `tests/test_tickets.py`). `tickets/README.md` and `AGENTS.md` describe the image gate's ticket-only exit, not the light test step.
  - `tests/test_ci_changes.py`, `WorkflowTest.test_light_path_steps_of_the_main_job` (AC-ENG-120-05), asserts exactly one step with `-p 'test_tickets.py'` and exactly five heavy steps (lines containing `unittest discover -s tests -v` or `examples/demo.py`). The new light command must keep that count at five.

## Requirements

- Scope: the light path of `.github/workflows/ci.yml` and, if Decision 1 chooses option B, `scripts/ci_changes.py` and its tests, plus the matching sentence in the documents that describe the light path ([docs/development.md](../docs/development.md) and `tickets/README.md`, wherever ENG-120 describes it).
- After this ticket, a change that touches only `tickets/` either runs every test module that reads real files under `tickets/`, or runs the full suite. Which one follows Decision 1.
- A ticket-only change that edits only ordinary ticket files (`tickets/<ID>.md`, `tickets/ROADMAP.md`) still skips the demo reports, the Docker jobs and the image build.
- A test fails if a test module reads files under `tickets/` and the light path does not run it, so the gap cannot reopen silently. How it detects this follows Decision 2.
- No change to which paths count as image inputs, to the publication or language checks, or to `pr-check`.
- Non-goals: making the full suite faster (ENG-105), changing what `test_agent_definitions.py` asserts.

### Interfaces

Module-level additions to `tests/test_ci_changes.py`, next to `workflow_jobs()` and `steps_of()`:

```python
LIGHT = "needs.changes.outputs.ticket_only == 'true'"
LIGHT_RUN = 'PYTHONPATH=src:tests python -m unittest -v '
# A module that reads real files under tickets/: names the directory, or lists or globs the repository.
TICKET_READER = re.compile(r"""tickets/|['"]tickets['"]|ls-files|ROOT\s*\.\s*r?glob\(""")
# Modules that match TICKET_READER but never read the repository's own ticket files.
NOT_TICKET_READERS = {
    'test_ci_changes.py': 'writes tickets/ files only in synthetic repositories',
    'test_pr_image.py': 'writes tickets/ files only in synthetic repositories',
    'test_publication.py': 'names tickets/ paths only as path_allowed inputs and in synthetic repositories',
}

def light_test_modules() -> list[str]:
    """File names of the modules the light-path step runs, in workflow order."""

def ticket_file_readers(tests_dir: Path) -> set[str]:
    """Names of the test_*.py files directly under tests_dir whose source matches TICKET_READER."""

def uncovered_ticket_readers(tests_dir: Path, light: list[str], allowed: dict[str, str]) -> set[str]:
    """ticket_file_readers(tests_dir) minus light minus allowed."""
```

- `light_test_modules()`: take `steps_of(workflow_jobs()['python-312-linux'])`; keep the steps that contain the line `'        if: ' + LIGHT`; there must be exactly one (raise `AssertionError` otherwise). Its `run:` line, stripped of the leading `        run: `, must start with `LIGHT_RUN` (raise `AssertionError` otherwise). Split the rest on whitespace; each word must match `test_[a-z0-9_]+` (raise otherwise); return `[word + '.py' for word in words]`. On the final tree it returns `['test_tickets.py', 'test_agent_definitions.py']`.
- `ticket_file_readers()`: read each file with `encoding='utf-8'`; do not import the modules. On the final tree it returns the five names listed in Context.
- Use only the standard library and the helpers already in the file. Do not add a YAML parser.

## Decisions needed

1. How to close the gap.
   - Option A (recommended): keep the classifier as it is and run every test module that reads files under `tickets/` on the light path. Today that adds `tests/test_agent_definitions.py`, which runs in seconds and needs no Docker. This is the only option that also covers the provider-ID scan, which reads every ticket file, and it keeps the image gate unchanged.
   - Option B: treat `tickets/README.md` and the other rule files under `tickets/` (for example `PORTABLE_PROMPT.md`, `TICKET_CHANGES.md`) as not ticket-only in `scripts/ci_changes.py`, so editing them runs the full suite. It is simple to reason about, but it leaves the provider-ID scan uncovered for ordinary ticket files, makes rule edits run the Docker jobs and the image build, and needs a list of rule files that someone must keep current.
   - Option C: both A and B. It covers everything, at the cost of B's extra runs.
2. How a test detects a new module that reads `tickets/`.
   - Option A (recommended): the light-path module list is written in one place (the workflow, or a constant in `scripts/ci_changes.py` that the workflow reads), and a test checks that every module under `tests/` whose source mentions `tickets/` together with a file read is on that list, with a short allowlist for modules like `test_publication.py` that only name such paths.
   - Option B: no automatic check; add a sentence to the testing guide that a test reading `tickets/` must be added to the light path. Cheaper, but the gap can return unnoticed.
   - Planner note (2026-11-25): the Build plan keeps the list in the workflow, because under Decision 1 option A the Requirements do not open `scripts/ci_changes.py`. The detector also flags modules that list or glob the repository (`ls-files`, `ROOT.glob`, `ROOT.rglob`), because the provider-ID scan reads every ticket file without naming `tickets/` (Context).
3. Scope of the test file (proposed change to a gated section, for the owner to approve at Gate A). Under Decision 1 option A, the Requirements scope names only `.github/workflows/ci.yml` and the documents; `scripts/ci_changes.py` "and its tests" are in scope only for option B. AC-ENG-121-03 needs a unit test, and the existing AC-ENG-120-05 test in `tests/test_ci_changes.py` asserts the current light step, so the build must edit `tests/test_ci_changes.py` under either option.
   - Option A (recommended): replace the first Requirements bullet with this text: "- Scope: the light path of `.github/workflows/ci.yml`, its tests in `tests/test_ci_changes.py`, and, if Decision 1 chooses option B, `scripts/ci_changes.py`, plus the matching sentence in the documents that describe the light path ([docs/development.md](../docs/development.md) and `tickets/README.md`, wherever ENG-120 describes it)." This changes the spec hash, so Gate A would approve the new text.
   - Option B: keep the Requirements as written and read AC-ENG-121-03 as authorizing the test file. No hash change, but the scope sentence and the build would disagree.
   - Recommendation: A. The Build plan above already assumes `tests/test_ci_changes.py` is in scope.
