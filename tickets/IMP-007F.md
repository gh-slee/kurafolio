# IMP-007F: Add the dedicated import worker and trusted launcher

## Goal

Run normalization in a dedicated worker that leases members, launches the parser in an isolated child, and finishes or cleans up through the SQL functions.

### What to build

Two processes, in two pull requests if that keeps each review small (worker first, launcher second; say so in the Handoff).

1. The import worker. A long-running process with its own restricted database role. It loops: claim work with `claim_plan_v1`, do it, report through the worker SQL functions, repeat. The kinds of work are normalize (run the parser on received bytes), prepare (build the preview after decisions) and cleanup (remove what a finished, cancelled or expired set left behind). It renews its lease at least every 10 seconds; a lease lasts at most 60 seconds on the database clock (30 s for normalize and cleanup in the merged functions). A worker whose lease has lapsed must not publish a result: every SQL call carries the fence it was given and the database refuses a stale one.
2. The launcher. A separate small service that starts the parser in a throw-away container and returns its output. The worker talks to it over a private authenticated channel. The worker has no Docker socket; the launcher has no database credentials. The parser container has no network, a read-only root, no private mounts, and CPU, memory, process and output limits. Only operator-pinned images run; nothing is pulled automatically.

Rules that reviewers will check:

- Received bytes live in memory or tmpfs for at most 120 seconds and are never written to the database, a queue or a log. If they are lost before the parser result is admitted, the member becomes `reupload_required`.
- Cancel, restart and recovery touch only containers this launcher started, matched by exact ID and its own labels. No kill-all, no prune, no adoption by name.
- A cleanup that cannot prove the raw bytes and the container are gone keeps the storage reservation and reports the failure. It never frees capacity it cannot prove is free.
- The owner's machine is an Apple Silicon Mac with Docker Desktop (owner decision 2026-11-11). The worker and launcher must run there inside the OPS-021 compose stack. Docker Desktop runs containers in a Linux VM, so record separately which controls are effective there and which are only proven on native Linux in CI.
- Contracts: `runner.md`, `protocol-appendix.md`, `wire-contracts.json` and `r7-native-policy.md` in the r7 bundle. The client half already exists in `src/kurafolio/ingestion/runner_client.py`; `src/kurafolio/ingestion/discovery.py` and `mapping.py` hold the checks the worker applies to parser output.

### Interfaces

Child profile: `create` uses exactly these flags, the values from `protocol-appendix.md` and `tests/test_source_harness.py` `PROFILE`: `--user 10001:10001 --read-only --cap-drop ALL --security-opt no-new-privileges --network none --ipc none --tmpfs /tmp:rw,noexec,nosuid,nodev,size=33554432,uid=10001,gid=10001 --memory 268435456 --memory-swap 268435456 --cpus 1 --pids-limit 16 --ulimit cpu=2:2 --ulimit nofile=64:64 --ulimit core=0:0 -i`, plus the entry point above and no `--env`, `--volume`, `--mount`, `--privileged`, `--device` or `--add-host`. Timeouts: setup and control 30 s; execution 10 s from the engine's `State.StartedAt`; stop and reap 5 s; stream joins 2 s; removal 5 s. The raw deadline caps every phase. Stdout is read through `ChildOutputCollector`. Stderr is drained to at most 64 KiB and never stored or logged.

Launcher outcome classification, checked in this order: stdout or stderr overflow gives `output_limit` (overflow wins even if the exit raced); execution past 10 s from `StartedAt`, or the raw deadline, gives `wall_limit` after the launcher kills the child; `State.OOMKilled` true, exit status 137 without a launcher kill, or a signal exit from `RLIMIT_CPU` (SIGXCPU or SIGKILL) gives `resource_exit`; any other nonzero exit gives `child_error`; a frame that `unpack_result` refuses gives `frame_rejected`. A fork refused by `--pids-limit` does not end the child by itself; the outcome is whatever the child then does under this rule.

Handoff refusals: a refused handoff returns HTTP status `contracts.ERROR_STATUS[code]` with the canonical body `{"code": <code>}` and nothing else. `HandoffAck` is returned only with status 202. IMP-007U (the upload route, which moved out of IMP-007E in PR #87) tests against a fake worker, so its plan and this shape must match; if they differ, stop and ask. `http.server.BaseHTTPRequestHandler.log_message` and `log_error` are overridden on both servers so that only the method, path, status, error code and request ID are logged, never headers, bodies or peer certificate details.

Worker journal (D4, owner decision 2026-11-20). It lets a restarted worker find the attempts it started and ask the launcher for their cleanup proofs.

- `WorkerJournal(directory: Path)`. On open, the directory must be a real directory (not a symlink), owned by the service UID, mode `0700`. Every entry must be a regular file with one link, owned by the service UID, mode `0600`, named `<job_id>-<fence>.json`. Anything else makes the worker refuse to start with the fixed code `journal_unsafe`, before any database or launcher connection.
- Record: canonical JSON (`codec.encode`) of exactly `{"version": 1, "set_id", "job_id", "member_id", "fence", "handle"}`. `handle` is `null` until the launcher answers `LaunchStart`. A record with an unknown or missing key, a wrong type, or a name that does not match its content makes the worker refuse to start with `journal_invalid`. The journal never holds raw bytes, context, results, the handoff token, a nonce, stderr, tenant or portfolio IDs.
- Writes: create a temporary file in the same directory with `O_CREAT | O_EXCL` and mode `0600`, write, `fsync`, `os.replace` onto the record name, then `fsync` the directory.
- Methods: `record(set_id, job_id, member_id, fence) -> bool`, `set_handle(job_id, fence, handle)`, `for_set(set_id) -> list[Record]`, `remove(job_id, fence)`, `records() -> list[Record]`. `record` is create-only: if a record for that job and fence exists, it leaves it unchanged and returns `False`; otherwise it writes the record and returns `True`. A retried handoff therefore never overwrites a handle.
- Write order on the normalize path: `record` after the handoff checks pass and before `claim_member_v1`; `set_handle` as soon as the first `LaunchStatus` answers `LaunchStart`, before any other launcher call.
- Removal: after `claim_member_v1` refuses a handoff whose record this handoff created (`record` returned `True`; this worker started nothing for it); after `finish_member_v1` succeeds with an `absent` or `not_created` proof, because finish then released the slot; after `cleanup_set_v1` for the record's set returns `purged` or `already_purged`.
- Known limits, which the docs state:
  - A crash after the launcher answered `LaunchStart` and before `set_handle` reached the disk leaves a record with `handle: null`. No proof can be obtained for that attempt, so its set stays `cleanup_pending` and keeps the slot and storage until an operator acts. The same holds for a bound attempt this worker never received (the handoff failed before it reached the worker) and for a crash before `record`.
  - After a credential epoch change, the launcher refuses controls that use a handle from the old epoch. Attempts from before the rotation get no proof and their sets stay `cleanup_pending`.

Worker loop. The worker is one process with three threads: the handoff server, the lease keeper and the pull loop. It has no database writes outside `WorkerSQL` and no durable state except the worker journal.

1. **Normalize (pushed by IMP-007U's upload route).** On a handoff:
   1. Check the peer, the frame and the `Handoff` fields. Refuse with `HandoffAck.outcome = reupload_required` if `raw_deadline` or `expires_at` has passed on the worker clock. The database still decides. If this process already holds an attempt for the same `job_id` and `fence` (a retried or concurrent handoff), answer `HandoffAck{outcome: already_owned, input_owned: true, stage_digest: null}`, drop the new copy of the bytes and do nothing else: no claim, no second launch, no journal change. Otherwise call `record`, and keep its result.
   2. Call `claim_member_v1` with `p_token = handoff_token` and request `{version: 1, realm_digest, credential_epoch, job_id, set_id, member_id, work_kind: "normalize", fence, request_id, raw_digest: raw_sha256, context_digest: context_sha256}`. `request_id` is `uuid5(<fixed namespace constant>, f"{job_id}:{fence}")`, so a handoff retried after a lost `HandoffAck` sends the same request and gets `already_claimed` rather than `import_conflict`. On `claimed`, keep raw and context in a `RawHold` (`bytearray`, zeroed and released on drop) that expires at `raw_deadline` no matter how often the lease is renewed, answer `HandoffAck{outcome: owned, input_owned: true, stage_digest: null}`, and go on to step 3. On `already_claimed` with no attempt in this process (the process restarted after the first claim), an earlier launch for that fence may still exist, so do not start a second one: answer with the fixed error `import_runner_unavailable`, drop the bytes and keep the journal record; the attempt then follows the crash path (D7). On `import_reupload_required`, answer `reupload_required` and drop the bytes. On any other error, answer with the fixed error code and drop the bytes. In both refusal cases remove the journal record only if `record` returned `True` for this handoff.
   3. `LeaseKeeper` calls `renew_member_v1` (new `request_id` each time, and always the same handoff token as `p_token`) every 10 s or sooner, and at the latest 5 s before `LeaseAck.expires_at`. Always take expiry from `expires_at`; never assume a fixed length. The first renew error marks the lease lost: the job stops, cancels its launcher attempt, drops `RawHold` and makes no further call with that fence except a `finish` that the database may refuse.
   4. Start the launch with `LaunchStart{operation: "start", job_id, member_id, fence, instance_id, realm_digest, credential_epoch, installation_id, image_digest, wrapper_profile_digest, format_version (all from the decoded child context), context_sha256, context_bytes, raw_sha256, raw_bytes, deadline: raw_deadline, nonce: secrets.token_hex(32)}`. Write the returned `handle` to the journal. Poll `LaunchControl{operation: "status", include_result: true}` until the state is `result_ready` or `failed`, or the raw deadline passes.
   5. On `ok`: `unpack_result` against the expected bindings, then `admit_parser2` or `admit_native` with the descriptor and the wrapper profile that match `installation_id` and `wrapper_profile_digest` exactly. If there is none or more than one, finish `rejected` with `import_evidence_unsupported`. Then call `admit_stage_v1` with `p_bytes = minimal`, `stage_digest = sha256(minimal)`, `discovery_digest = sha256(child payload)`, `raw_digest` and `payload_bytes = len(minimal)`. Clear `RawHold` and every payload buffer as soon as `admit_stage_v1` returns, whatever the outcome.
   6. Wait for the cleanup proof (D8, option F). Send `cancel` if the attempt is still running. Then poll `status` (`include_result: false`) every 500 ms until the launcher reports `finished` with `cleanup_complete: true` (proof `absent`) or that no engine object was created (`not_created`), or until `raw_deadline` minus 5 s, whichever comes first. `LeaseKeeper` keeps renewing during the wait. The lease cannot outlive `raw_deadline`, so the wait must end in time for `finish` to land under a live lease. If the wait ends without `absent` or `not_created`, use the latest `pending` or `failed` proof. Send `forget` only after an `absent` or `not_created` proof; otherwise keep the launcher's record so that a later cleanup can still ask for the proof by handle.
   7. Call `finish_member_v1` with `outcome` and `error_code` from the table below and `cleanup_proofs = [proof]`. With an `absent` or `not_created` proof the merged SQL releases the raw slot here; remove the journal record. With a `pending` or `failed` proof the slot stays held until the set ends and a cleanup lease proves it; keep the journal record. Releasing it earlier after a late proof is IMP-007Q's work.

   | Launcher outcome or worker event | `finish` outcome | `error_code` |
   |---|---|---|
   | `ok` and stage admitted | `stage_admitted` | `null` |
   | `output_limit`, `resource_exit`, `wall_limit` | `rejected` | `import_limit` |
   | `child_error`, `frame_rejected`, or a payload refused by `unpack_result` or `admit_*` with `import_invalid` | `rejected` | `import_invalid` |
   | `admit_*` refuses with `import_evidence_unsupported` or `import_stale` | `rejected` | the same code |
   | `context_rejected` | `rejected` | `import_stale` |
   | launcher unreachable, `cancelled` by this worker, `cleanup_failed`, or raw deadline reached before admission | `reupload_required` | `import_runner_unavailable`, or `import_reupload_required` for the deadline |

   Under the merged SQL, a `rejected` finish rejects the whole set (`test_finish_rejection_rejects_the_whole_set`), so one over-limit or invalid file ends every member of its set. The docs must say so.

   A `CleanupProof` is `{job_id, fence, state, launcher_instance_id, checked_at, proof_digest}`. `state` is `absent` when the launcher reports `finished` with `cleanup_complete: true`, `not_created` when the launcher reports that no engine object was ever created for that nonce, `pending` while removal is in progress, and `failed` after a failed removal. `checked_at` is a UTC `Instant` from the launcher's status. `proof_digest = codec.digest(<the LaunchStatus object the proof was read from>)`. The DB checks only the shape, so this definition is the plan's choice; if the reviewer or owner wants another one, stop and ask.
2. **Prepare (pulled; PR 3 only).** Loop `claim_plan_v1{work_kind: "prepare", claim_request_id: <uuid4>}` with a fresh `secrets.token_hex(32)` token. After `no_work`, sleep 1 s plus up to 1 s of jitter. After `claimed`, read every basis resource with `read_plan_basis_v1` (cursor paging, `limit` 50) under the lease, build the `ReviewBundle` with IMP-007P's builder, check it with `approval.validate_review_bundle`, and call `prepare_preview_v1` with `p_bytes = codec.encode(bundle)` and the pins from the lease and basis. One lease covers the whole step and is never renewed (D6). If less than 5 s remain before `expires_at`, give up the work: send no further calls, and the next claim after expiry starts again. Never reuse a token or a `claim_request_id`.
3. **Cleanup (pulled).** Loop `claim_plan_v1{work_kind: "cleanup"}` the same way. For the claimed set, take the journal records of that set (`for_set`). For each record with a handle, ask the launcher for `status` and turn the answer into a proof; records without a handle give no proof. Send at most 12 proofs in total and 1 per attempt, and call `cleanup_set_v1`. On `purged` or `already_purged`, remove the set's journal records. On `cleanup_pending`, keep them; the database keeps the reservation and a later claim retries. One lease covers the step and is never renewed (D6). Do not assume oldest-first order (IMP-007N).
4. **Startup.** Open the journal (refuse to start on `journal_unsafe` or `journal_invalid`). The worker holds no `RawHold` after a restart and does not try to finish old attempts: their handoff tokens died with the old process. Their records wait for the cleanup of their sets.
5. **Shutdown (SIGTERM).** Stop accepting handoffs and claims, cancel running launches, drop every `RawHold`, and exit within 10 s. Keep journal records. Leases lapse on the database clock. No call tries to end them early.

Launcher on restart: read the journal; for each record that is not `finished`, `kill`, then `rm --force` the exact engine ID, mark it `cleanup_pending` until `inspect` reports the ID absent, then `finished`. For a `created` record with no engine ID (a crash between create and journal write), find the container only with the exact `instance` plus `nonce`-digest label filter and remove it. Any late result from before the restart is discarded. Records stay until the worker sends `forget`, so the worker can still read a proof after a launcher restart. Credential epoch change: refuse every control from the old epoch, reconcile its children, then accept the new epoch.

Instance activation: not in this ticket. IMP-007S builds the operator command (D1). Every test here seeds `wl_ingestion.instance_state`, `instance_budgets` and `workers` through the operator role exactly as `tests/test_postgres_migration.py` does today.
