# IMP-107: Find and fix the intermittent failures in two PostgreSQL import tests

## Goal

Two tests in the opt-in PostgreSQL import suite failed once in CI on a change that touched only Markdown, and passed on another run of the same commit. A test that fails at random makes every agent distrust CI, and it can hide a real fault in the import SQL. Find out why these two tests fail intermittently, fix the cause, and make any future failure in this suite say what went wrong.

## Context

- Failing run: https://github.com/gh-slee/kurafolio/actions/runs/44134551604 (pull request event for PR #66, commit `cbf2d83`, Markdown-only change), job `postgres-ingestion`. The push event for the same commit passed that job: https://github.com/gh-slee/kurafolio/actions/runs/44134537862.
- Failed tests, both in `tests/test_postgres_migration.py`, class `IngestionAppendOnlyPostgresTests`:
  - `test_plan_entry_raw_bounds_and_canonical_rejections`, subtest `code='import_limit', size=16777217` (line 1344, through `_assert_plan` at line 1287). It sends a 16 MiB + 1 byte input, hex-encoded (about 33 MB of SQL text), in a single statement.
  - `test_prepare_preview_checks_initial_and_ready_bundles_and_replays`, subtest `ready=True` (line 4682).
- The helper `sql()` (around line 899) runs `psql` through `docker exec` with a 45 second timeout and raises `AssertionError('Synthetic PostgreSQL fragment statement failed')` on a non-zero exit, discarding `psql`'s error output. The CI log therefore does not show the database error.
- The test container runs with `--memory 512m --cpus 1 --pids-limit 128` (line 937). The import SQL in `src/kurafolio/persistence/ingestion_schema.py` sets no statement or lock timeouts.
- Hypothesis, not verified: the 33 MB statement can exhaust the container's memory on a busy runner. The second test's cause is unknown.
- CI job definition: `.github/workflows/ci.yml`, job `postgres-ingestion`, which runs `scripts/run_gated_tests.py --expect-skipped 0`.

## Requirements

- Failures in this suite report the database error (SQLSTATE and message from `psql`). Inputs are synthetic, so the message may be shown; very long statement text is truncated in the report.
- The fix addresses the measured cause. It does not add retries, does not raise the suite-wide timeout, and does not skip either test or subtest.
- The tests keep checking the same behaviour, including the rejection of an input one byte over the 16 MiB limit with `import_limit`.
- If the cause is in the import SQL rather than the tests, the change follows the approved import contract; a change to a documented limit or behaviour goes to the owner first.
- Non-goals: other flaky tests (ENG-107 covers the browser test), CI speed (ENG-105).
