# ENG-114: Publish the shared spec material that tickets cite

## Goal

About 20 open tickets cite material that exists only on the owner's machine: the untracked V2 planning package under `docs/specs/`, the ignored import contract under `work/`, and golden cases such as G07 and G19. An agent in another tool, on another machine or in another person's clone cannot read them, so those tickets are not complete specs. Make every cited item available as a reviewed, tracked document, or fold it into the ticket that needs it.

## Context

- Rule: a ticket may depend only on tracked documents ([spec-development.md](../docs/spec-development.md#the-ticket-is-the-spec)).
- ENG-016 proposes publishing the whole planning package and has no approval; this ticket covers only what tickets cite.
- Claimable today and affected: ANL-008 cites golden case G07; IMP-007E, 007F and 007G cite the r7 contract bundle.
- Count on `main` at `865a671`: 20 open tickets cite `docs/specs/`, `work/`, a golden case, a spec revision or the contract bundle. In seven of them (ANL-008, ANL-012E, ETF-010, ETF-010B, MKT-009B, MKT-009C, OPS-015) the citation is inside Acceptance criteria, a gated section. The Build plan inventory found nine: IMP-007E and IMP-007N also cite the r7 bundle there.
- ENG-113 uses the same `ticket-bulk-edit` resource, so the two tickets run one after the other.
- ENG-016 has the same aim for the whole planning package, no approval, and a criterion this ticket keeps: the owner reviews the exact file list before commit.
- Publication rules: [publishing.md](../docs/publishing.md), [SECURITY.md](../SECURITY.md), `scripts/check_publication.py`.

## Requirements

- Scope: only what open tickets cite. The rest of the planning package stays local, and ENG-016 is closed as superseded by this ticket.
- Inventory every citation of `docs/specs/`, `work/`, golden case IDs, spec revisions and the contract bundle in open tickets.
- For each, publish a sanitised copy under tracked `docs/` and link it from the ticket's Context. Do not edit gated sections, so approved hashes stay valid; a citation inside a gated section is resolved by a Context link to the tracked document that holds it.
- Golden cases live in one tracked `docs/golden-cases.md`.
- Before anything is committed, the owner reviews the exact list of files to publish and their sanitised content.
- Link documents that set expected values at a commit (or record their content hash), and say in the document that changing an expected value requires re-approval of the tickets that cite it.
- Golden cases keep their IDs, inputs and expected values exactly.
- Nothing private is published: no account names, real amounts, personal paths, transcripts or approval evidence.
- Non-goals: rewriting the planning package, changing any requirement.
