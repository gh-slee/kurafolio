# MKT-101: Probe the quote providers with real keys, choose one and add its adapter

## Goal

Stock, ETF and bond prices can be fetched today only through the optional unofficial adapter, which can break without notice and whose terms of use are unclear. The supportable path is a documented provider used with the instance operator's own API key. MKT-009E started that work and stopped where an agent could go no further: it needs real provider keys, which only the owner can create. The owner chose on 2026-11-16 to supply the keys later, so that go-live does not wait for them. This ticket holds everything that is left: run the probe with real keys, let the owner choose a provider, then add its adapter.

## Context

### Background

- Continues MKT-009E, which is closed as superseded. Nothing from it is on `main` yet. Its work is three commits on the branch `ticket/wl-p0-009e-choose-and-add-an-official-keyed-quote-p` (pushed to `origin`), and this ticket's `branch` field points there, so a claim continues on that branch.
- Already done on that branch: `docs/market-provider-spike.md` (documented limits, delay, Toronto coverage and licence terms for Alpha Vantage, Twelve Data, Finnhub, EODHD and Tiingo, read from each provider's own pages on 2026-11-12, plus the test plan), the probe `scripts/market_provider_spike.py`, and `tests/test_market_provider_spike.py`.
- What the desk research already rules out: Tiingo's Starter terms forbid storing data, and Tiingo and free Finnhub have no Toronto coverage. The realistic candidates are Alpha Vantage, Twelve Data and EODHD, with Finnhub optional.
- Consequence of deferring: at go-live, live security prices come from the unofficial adapter if the operator enables it, and otherwise from the market values in the imported file, marked "as of the source file". Bitcoin and exchange rates are unaffected.

### Scope

- In scope: the real-key probe run, the "Measured results" and "Recommendation" sections of the report, the owner's choice, one adapter behind the MKT-009A interface, provider ordering with the unofficial adapter, tests with recorded synthetic responses, the operator guide.
- Out of scope: the price store and scheduler (MKT-009B), a second official provider, paid real-time data, anything that needs the key inside the repository or a test.

### Implementation notes

- Part 1, the probe (needs the owner). The owner creates free keys for Alpha Vantage, Twelve Data and EODHD (Finnhub optional) and saves each as one line in `~/.config/kurafolio-spike/<provider>.key`, outside the repository. Then either the owner runs the probe as the report's test plan describes, or an agent session that the owner gives access to that directory runs it. No agent creates a provider account.
- The probe checks, per provider: latest quote and daily history for two Toronto-listed ETFs, two US-listed ETFs, one stock on each market and one bond or bond ETF, and the observed delay. EODHD's free tier allows 20 calls a day, so its probe runs once; do not re-run it to "check".
- Part 2, the choice (the owner). Fill "Measured results" and "Recommendation" in the report, including the request budget for 10, 30 and 100 distinct listings at the default refresh intervals against each free limit. The owner picks one. Record the choice in this ticket's Log before any adapter code.
- Part 3, the adapter. It implements the MKT-009A interface (`src/kurafolio/market/`), reads the key from an operator secret file, and reports its delay class truthfully. With no key file it is inactive and sends nothing.
- When this adapter and the unofficial one are both enabled, the operator sets the order. A listing the first cannot serve falls through to the next, and every stored price names its source.
- Fetch unadjusted closing prices for history, and record whether the provider back-adjusts for splits (see the gotcha in MKT-009D).
- The operator guide explains how to get a key, where to put it, the request budget for a typical portfolio, and that opening an instance to the public may need a paid licence.
- Never commit a key, an account identifier or a response containing one. Recorded responses hold public market data only, trimmed to the fields used.

## Acceptance criteria

- [ ] The spike report covers at least two providers with the listed instruments, measured with real keys, and quotes each provider's limits and licence from its own pages with the date read.
- [ ] The report states the request budget for 10, 30 and 100 listings against each free limit, and recommends one provider.

- [ ] Given recorded responses, then latest quote and daily history for a Toronto-listed and a US-listed symbol return the oracle values with currency, "as of" time and delay class.
- [ ] Given no key file, then the adapter is inactive and no request leaves the instance.
- [ ] Given a rate-limit response, then the adapter stops for the period the provider states and the store keeps the last valid price marked stale.
- [ ] Given two enabled providers in a set order, then a listing unknown to the first is served by the second and the stored price names the second.
- [ ] No key appears in logs, errors, the repository or test fixtures.
- [ ] The operator guide covers getting a key, where it goes, the request budget and the licence note.
