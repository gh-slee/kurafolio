# F07-03: HTTP, worker and launcher protocol

wire-contracts.json fixes every new public route, closed request/response/error DTO and the private handoff/launcher/event DTO. Required fields are always present, using null where specified. Source/full-plan internals are not public DTOs. Existing identity/source/default routes remain unchanged. Version strings and proposed operation names describe the implementation contract, not commands available today.

## Public boundary and state

Exactly nine method/path entries are added under explicit ingestion profile. Path placeholders are nonzero UUIDs. Unknown queries/duplicates reject; list/preview query keys are cursor,limit and optional exact state for lists, limit1..50. Cursors are MAC-bound opaque server tokens using HMAC-SHA256 with a dedicated derived purpose key, binding current principal/scope/realm/filter/page revision and position; no raw financial values in cursor payload/logs. Do not reuse sessions/invite tokens as cursors or a receipt ID as authority.

JSON control input stays16,384 bytes/10s. Raw PUT requires one positive Content-Length1..10,485,760, application/octet-stream, no Content-Encoding/Transfer-Encoding/Expect. Host/origin/CSRF/identity/header syntax and recognized route are checked before pulling the body; authentication denial never starts a parser. Missing length411, duplicate/CL+TE400, wrong media/encoding415, oversized413, deadline408. Count exact ASGI bytes including extra trailing chunks; short/extra/disconnect before complete body cannot hand off. Total30s, idle5s. Body buffering to durable disk in framework/proxy is unsupported for this route. The public API does not read a client-provided path or accept original filename.

GET responses are no-store/private, max50 rows/page and at most 4 MiB+16 KiB total canonical JSON, with fewer rows and a cursor as necessary. No binary floats, DB host/port/DSN/session digest/private file path or raw/source_fields in responses. Error messages use existing generic en-CA/zh-TW/zh-CN messages and request_id, never parser stderr or driver exception. Fixed codes/statuses are in wire-contracts.json. Identity/source errors from their existing guards keep their accepted precedence; no new import detail is returned before live auth.

Public operations use scoped realm+operation UUID namespace and canonical request digest. For confirm the digest covers kind, preview UUID and supplied exact digest; operation UUID is the lookup key, not a financial field. A proven receipt is read before fetching an expired/purged preview. Same operation with a different kind/payload conflicts; a new operation with duplicate facts is an explicit no-change result. GET historical receipt requires fresh current auth; old realm history never grants POST authority.

Create returns201, or200 for an exact known CREATE replay. PUT decisions returns202 after saving immutable decisions and scheduling preparation; state is RECONCILING until worker stores a validated preview, then NEEDS_MAPPING/CONFLICT/READY. No hidden synchronous financial write. Raw PUT returns202 only after authenticated worker acknowledges complete input ownership; polling establishes stage admission. Cancel returns CANCELLED when it wins, or COMMITTED/receipt when commit won. CONFIRMING remains transaction-local. If any member needs re-upload/mapping/conflict, set cannot be READY. Terminal states never revive. Raw re-upload before set expiry creates a new attempt/fence; format/alias/version changes require a new set.

## Shared capacity and raw ownership

Before reading raw, reserve user 1/instance 4 active raw slots under PG shared locks and a member fence. Eight outstanding sets/user and 64/instance reserve at most 16 MiB/set,128 MiB/user and 1 GiB/instance minimal storage. Each selected set has at most 4 members. Row/field/payload bounds are intersections, not a promise that a 40,000-row set always fits 16 MiB. Rate buckets use the selected 300s windows; invalid admitted attempts consume rate budget but not financial generations. Do not replace shared limits with per-process counters.

reserve_member_v1(action=reserve) anchors raw_deadline at DB clock+120s, which is no later than120s after first body byte. API enforces its own monotonic receive budgets. action=bind fixes actual hash/count and digest of a fresh256-bit handoff token after full reception. Offer expires in<=60s and before raw_deadline. No durable raw queue. Token is sent only over API-to-worker mTLS; public response never contains it. Worker claim verifies live originating session/source, exact realm/member/fence and token hash, then consumes the offer. DB bytea stage inputs are already strictly admitted minimal/plan bytes, never raw.

After handoff loss, API/worker queries the exact saved attempt/stage before starting anything again. An already admitted stage recovers by its digest. If no provable stage/raw ownership survives, mark reupload_required, fence the old attempt and require new bytes. Do not rerun a parser merely because a COMMIT or launch acknowledgement was lost. Launch start with the same nonce/content returns its owned status/result; it cannot create a second child. Memory-only result retention ends after acknowledged stage admission or the original120s budget, whichever occurs first. No payload in durable launcher journal.

Raw/context/result buffers are bounded and cleared when their owner finishes. Cancel/expiry fences first; active slot/storage reservation is released only after exact child/payload cleanup is verified. Cleanup failure retains count and explicit cleanup_pending/unavailable state, preventing overcommit. Periodic cleanup may run only as a foreground existing worker loop, not a new cron/agent scheduler; it cannot delete accepted evidence. Lease heartbeat<=10s, lease lifetime<=60s, total raw lifetime never extends with heartbeat.

## Private peers and framing

Initial topology is one self-hosted Docker instance/engine with Linux containers; this is not multi-host orchestration. API, trusted ingestion worker and trusted launcher are separate processes/containers. Internal endpoints have no host-published port. Require TLS1.3 and mutual certificate validation against an operator-provisioned private CA, valid dates/key usage and exact configured DNS+URI peer identity. Peer URI format is urn:wealth-ledger:instance:<nonzero UUID>:peer:api|worker|launcher. API client identity is accepted only by worker; worker identity only by launcher. No shared browser cookie/DB password or fallback plaintext. Secret mounts are read-only and accessible only to the intended service UID; no child mount. CA/server/client key files are never created by an end-user CSV request.

Worker HTTP POST /internal/v1/handoffs receives the closed Handoff metadata, then exactly declared context and raw bytes. Header frame is uint32 big-endian JSON length<=16 KiB, then canonical metadata JSON, then context bytes and raw bytes with no trailing data. Whole request length is predetermined; no chunked framing, no compression. Worker validates peer/offer before accepting buffers, hashes actual bytes, consumes claim once and returns an opaque job/fence acknowledgement. A context hash mismatch or EOF rejects without any accepted effect.

Launcher POST /internal/v1/jobs accepts LaunchStart metadata in the same length-prefix format, context<=1 MiB then raw<=10 MiB. Controller requests POST /internal/v1/control use closed LaunchControl canonical JSON<=16 KiB and no extra stream. start nonce and handle are64 lowercase hex characters from independent256-bit random values. Source profile fixes wrapper/image/entry point; caller shell/env/flags/path/command/image tag/pull/build fields are unknown and rejected. Worker never gets a general Docker API.

Child stdin is a fresh length-prefixed canonical minimal adapter context plus raw bytes; it contains only job/fence, exact format/profile and source parser context/ephemeral discovery namespace. Child never gets real tenant/portfolio, auth realm, worker token/cert, DB/socket or portfolio path. Child stdout is uint32 header length<=4 KiB + exact payload<=4 MiB; header is LaunchResult without the parent-issued handle (launcher adds its own handle after verifying). Parser2 payload is frozen canonical batch bytes; native payload is closed NativeDiscovery. Drain stderr concurrently up to64 KiB and never log its contents. Reject oversized/truncated/trailing bytes, wrong hash/binding, duplicate JSON keys and nonzero/error exit before decoding/admission. Overflow wins over JSON interpretation even if exit raced.

Launcher status JSON reveals only same-owned opaque attempt state. include_result=true returns the bound LaunchResult+payload frame only to the same worker/realm/credential epoch while memory is available. cancel only targets exact owned engine ID and labels; forget removes terminal journal metadata only after absence and consumed/discarded payload. No arbitrary read path, command injection, cross-job status or broad kill/prune. Every journaled ownership token is a digest; plaintext handle/nonce is not logged.

## Native controls and restart

The selected concrete child profile remains UID/GID10001, read-only root, network/ipc none, cap-drop ALL, no-new-privileges, no host/DB/socket/user mounts; private32 MiB noexec/nosuid/nodev tmpfs; memory256 MiB, memory-swap256 MiB, CPU1, PIDs16, RLIMIT_CPU2s/2s, nofile64/64, core0/0. Environment is exactly PATH=/usr/local/bin:/usr/bin:/bin, LANG=C.UTF-8, LC_ALL=C.UTF-8, TZ=UTC, HOME=/nonexistent, PYTHONDONTWRITEBYTECODE=1, PYTHONHASHSEED=0, PYTHONUNBUFFERED=1. No inherited arbitrary env. Operator-installed pinned image only; no pull.

Setup/control30s; execution10s from actual engine StartedAt; stop/reap5s, stream joins2s, exact removal5s. Raw120s deadline dominates all phases. Effective controls are inspected and native denial/resource/descendant probes actually executed for the declared engine/architecture. Missing/ineffective required limits fail readiness; Docker installed is insufficient. Rootful engine control remains trusted host-level authority; Desktop VM/shared-resource boundaries are distinct. No native Windows containers or inference of native macOS/Windows sandbox proof.

Journal states created/started/result_ready/failed/cleanup_pending/finished bind instance, peer, credential epoch, realm digest, job/member/fence, nonce/handle digests, engine ID, immutable image and deadlines. On create-before-journal crash, reconcile only exact instance+nonce labels; never adopt by name/PID. On restart kill/reap owned old attempts, reject late output, require re-upload unless minimal admission is provable. Raw/result RAM is not recovered from journal. Operator credential/CA rotation fences ingestion leases, updates worker credential epoch and launcher allowed peers, reconciles old children and rechecks readiness before resuming. Already accepted facts/history are untouched; no automatic secret renewal or hidden cert provisioning.

## Database calls and events

Worker uses only the dedicated EXECUTE role and eight exact functions in sql-inventory.json; token+request+bytea are never placed in SQL text or exception output. Server/operator logging configuration must not log bind parameters, request bodies or child streams; hostile host/audit agents are outside the admitted privacy threat model. Direct SQL tests still verify grants/shape/scope/immutability. Trusted worker validation, not a digest alone, is the financial-normalization authority.

facts.accepted.v1 is the closed FactsEvent DTO, body<=4 MiB. A mapping-only invalidation has unchanged accepted_generation, incremented mapping_generation, empty changed revision/head lists and one event; it is not a market gain or new acquisition. Duplicate-only no mapping change has no event. Consumer failure cannot undo COMMIT; no consumer/valuation/report work is activated here.

## Retention and restore caveat

24h means logical expiry and deletion of live unaccepted payload rows/buffers; it is not a claim of secure physical erasure of WAL, existing dumps, snapshots or host RAM/swap. Those private copies remain subject to the declared backup/storage retention policy and must not be publicly published. Every restore cancels/purges unaccepted payloads before readiness, so an old dump cannot reactivate an expired preview. Full application backup-retention operations remain015; exact007 manifest/empty-target validation is mandatory now. Do not describe a successful DB DELETE as proof that all historical copies vanished.

Cursor key is HMAC-SHA256(instance secret, UTF8 wealth-ledger/ingestion-cursor-v1). Token is canonical cursor JSON encoded as unpadded base64url, a dot, then unpadded base64url HMAC over those exact JSON bytes. Payload keys are version, user_id, portfolio_id, realm_digest, resource_id|null, resource_revision|null, review_digest|null, filter, after_key and expires_at; all IDs opaque and filters fixed enums. Expiry is no later than current session absolute/idle expiry, additionally original set expiry for previews. MAC is checked before payload use, constant-time, with no client tenant override. Altered realm/scope/revision/filter or malformed/noncanonical encodings reject. The token is signed, not encrypted, and contains no financial values.

Inherited identity/source error codes and call-site statuses are enumerated separately in wire-contracts.json by static source inspection; their current precedence is unchanged. Import-specific status mapping is exact. Unknown implementation errors map to fixed internal_error/instance_not_ready, not arbitrary exception strings. Member error_code uses the same closed imported-code union, with normalization details mapped to safe import codes.

The child image's fixed entry point clears inherited image environment with env -i, sets exactly the eight declared variables, and invokes the fixed runner_child.py with isolated Python. A trusted bootstrap may add only fixed /app/src to sys.path for the source-only image; caller context cannot choose import paths. Container Config.Env alone is not proof of effective child environment: probe the actual interpreter. Launcher runtime-control access is operator-provisioned and tested on the engine; no automatic socket chmod/group/privilege escalation or application-worker access. A dedicated opaque launcher-journal volume is separate from financial volumes; no volume is created during planning.

The selected 16 MiB set reservation is an aggregate live transient payload budget: stages, contexts, decisions and previews, including retained superseded versions, all consume it. Per-member 4 MiB and per-set normalized 16 MiB remain upper bounds, not an additional unreserved allocation. A new stage/decision/plan that would exceed actual reserved capacity is rejected atomically with import_limit, leaving the earlier valid state intact; no hidden eviction, quota overcommit or financial partial acceptance. Content-free set/receipt/queue metadata is bounded by outstanding-set/rate/state limits. Cancel/expiry cleanup releases storage exactly once after deletion/child absence is proven.
