# WL-P1-003 — Support safe local plugin authoring and contribution review

## 1. Problem and user value

Independent package example/host enablement exists but user-facing store tutorial and V2 contract harness require extension (E08,E09,E24).

Local unofficial developer-instance workflow, synthetic fixtures/contract harness, tutorial and GitHub submission/official review checklist; no browser arbitrary code execution.

## 2. Scope, non-goals and risk

Shared architecture is proposed in [the overview](../architecture/OVERVIEW.md); detailed financial/security/migration choices require the linked ADR gates. Do not absorb another spec or reopen D01–D14 silently.

## 3. User journey and states

The affected journey and first-use/normal/empty/partial/stale/error/permission states are specified in [UX and API](../product/UX_AND_API.md). This slice implements only the bounded outcome above; skipped or unsupported states must be explained, not rendered as zero or success.

## 5. Canonical contracts and architecture

Expected paths above are a scoped proposal, not a claim those new modules exist. Reuse current services from [source evidence](../EVIDENCE_INDEX.md). [Canonical model](../architecture/CANONICAL_MODEL.md), [File/API lifecycle](../architecture/DATA_SOURCE_PLUGINS.md), [projection](../architecture/PROJECTION_VALUATION.md) and [PG plan](../architecture/POSTGRESQL_MIGRATION.md) define applicable boundaries. Any contract change outside this exact slice returns for Architect/owner review.

## 6. Security, reliability, migration and rollback

Malicious/oversized/unknown-version/conflicting package tests fail safely; production cannot enable unreviewed source through ordinary user UI. Rollback disables plugin, retains normalized facts.

High/critical review requires Architect, independent negative/golden evidence and explicit rollback/failure plan approval. Use only synthetic isolated test data; tenant/secret/plugin constraints in [security/ops](../quality/SECURITY_OPERATIONS.md) apply.
