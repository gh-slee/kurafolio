# WL-P0-014 — Migrate legacy ledgers with verified restore and cutover

## 1. Problem and user value

Current copy/backup/restore supports SQLite Web adoption, not PostgreSQL or acquisition-only scope migration (E22).

Build deterministic read-only-copy inventory/dry-run conversion/equivalence manifest and operator-approved freeze/cutover/recovery commands; original workspace retained.

## 2. Scope, non-goals and risk

Priority P0, size LARGE, risk CRITICAL. This is an individually reviewable draft, not an implementation grant. No personal imports, migrations, remote publication or deployment are included. Shared architecture is proposed in [the overview](../architecture/OVERVIEW.md); detailed financial/security/migration choices require the linked ADR gates. Do not absorb another spec or reopen D01–D14 silently.

## 3. User journey and states

The affected journey and first-use/normal/empty/partial/stale/error/permission states are specified in [UX and API](../product/UX_AND_API.md). This slice implements only the bounded outcome above; skipped or unsupported states must be explained, not rendered as zero or success.

## 4. Financial invariants and examples

Full source-target mapping, exact decimals/FKs/revisions/settings/bytes; separate legacy total equivalence from new Option A scope baseline. Multiple legacy portfolios require explicit user mapping.

Independent proposed cases: G17,G16,G13 in [golden cases](../../golden-cases.md). Expected values are fixed outside production calculations; future QA verifies independently.

## 5. Canonical contracts and architecture

Expected paths above are a scoped proposal, not a claim those new modules exist. Reuse current services from [source evidence](../EVIDENCE_INDEX.md). [Canonical model](../architecture/CANONICAL_MODEL.md), [File/API lifecycle](../architecture/DATA_SOURCE_PLUGINS.md), [projection](../architecture/PROJECTION_VALUATION.md) and [PG plan](../architecture/POSTGRESQL_MIGRATION.md) define applicable boundaries. Any contract change outside this exact slice returns for Architect/owner review.

## 6. Security, reliability, migration and rollback

Unknown schema/precision/pending work stops. Fresh old/new empty restores are mandatory. Before target writes reversible switch; after writes fence and forward/replay recovery, never stale fallback. Actual personal migration separate authorization.

High/critical review requires Architect, independent negative/golden evidence and explicit rollback/failure plan approval. Use only synthetic isolated test data; tenant/secret/plugin constraints in [security/ops](../quality/SECURITY_OPERATIONS.md) apply.
